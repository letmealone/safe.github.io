업무 우선 진입·노후건축물 정보조회·화면 복귀 보강안

작성일: 2026-09-15
주 사용자: 지자체 공무원, 점검·진단 전문기관 담당자
보조 이용자: 안전진단 관리가 필요하거나 검토 대상인 노후건축물의 공개 정보를 찾는 일반인

이 문서는 기존 플랫폼 관찰과 사용자 피드백을 바탕으로, 업무를 우선한 진입 구조와 이전 화면으로 돌아가는 경험을 설명한다. 앞선 보강판에서는 주 에이전트가 공개 조회, 목적지 로그인, 업무 복원, 공유·보완 흐름 등 25개 기능 동작을 확인했다. 이번 업무 우선 배치·대상 표현·복귀 동작 보강의 검증은 별도로 수행한다. 실제 운영 사이트의 인증·저장·공개 정책을 검증한 것은 아니다.

1. 이번 보강의 핵심

초기 화면의 왼쪽을 공무원·전문기관의 주 업무 경로로, 오른쪽을 비로그인 정보조회의 보조 경로로 배치한다. 이 서비스의 중심은 안전진단 관리가 필요하거나 검토 대상인 노후건축물을 관리하는 업무다. 일반 건축물 전체를 소개하는 검색 서비스처럼 보이지 않게 한다.

사용자 주로 하려는 일 기본 진입 이어지는 화면
지자체 공무원 담당 점검의 기한·기관 현황, 공유 결과·보완 사항 확인 왼쪽 업무 진입 → 로그인 후 대시보드 내 담당 또는 관할 업무 목록 → 점검건 → 필요한 지도·근거
전문기관 담당자 수행 중인 점검의 현장자료·보고서·보완 작업 계속하기 왼쪽 업무 진입 → 로그인 후 대시보드 내 담당 또는 기관 업무 목록 → 기존 작업·점검건
일반인 관리·검토 대상 노후건축물의 공개 안전진단 정보 확인 오른쪽 비로그인 보조 진입 주소 검색·공개 GIS 지도 → 대상 건축물의 공개 정보 → 공개용 sBIM

재접속 시에는 이전 작업을 이어갈 수 있게 하면서, 그 사이 바뀐 업무도 함께 알려준다. 지도 분석은 로그인한 업무 공간의 별도 탭에서 사용하고, 공개 조회는 로그인 없이 시작한다.

왼쪽 주 경로는 제목·설명·버튼의 순서에서도 먼저 읽히게 한다. 화면이 좁아져 세로로 쌓이면 업무 진입을 위에, 공개 조회를 아래에 둔다. 공개 조회는 필요한 사람이 바로 찾을 수 있는 명확한 보조 경로로 제공한다.

2. 기존 관찰 → 왜 불편한가 → 이번 대안

① 업무 이용자가 로그인한 뒤 자기 일을 찾아야 한다

기존 관찰: 첫 화면은 지도 중심이다. 정기점검 등 표 형태의 업무 화면은 하단 플랫폼 전환을 통해 관리자 공간에 들어가야 발견할 수 있었다. 소규모 노후건축물 점검은 sBIM 데이터 메뉴 아래에 있었다.

왜 불편한가: 공무원과 전문기관 담당자는 처리할 업무를 알고 방문한다. 하지만 시스템의 메뉴 구성을 먼저 이해해야 해당 건에 도달한다. 이미 익숙한 점검유형·회차·진행상태를 이용해 바로 시작하기 어렵다.

이번 대안: 초기 화면 왼쪽에 공무원·전문기관 업무를 우선 배치하고, 로그인한 계정의 소속·역할에 맞는 대시보드를 기본으로 제공한다. 공무원은 업무유형별 기한과 공유 결과, 전문기관은 현장자료·보고서·보완 작업을 먼저 본다. 역할을 매번 다시 고르는 절차는 실제 제품의 기본 이용 흐름에 넣지 않는다.

② 재접속할 때 이전 작업과 새 상황을 함께 파악하기 어렵다

기존 관찰: 앞선 가상 시안은 로그인·초기화 때 정해진 예시 상태로 돌아갔다. 실제 운영 사이트의 재접속 복원 동작은 이번 읽기 중심 탐색으로 확인하지 않았다.

왜 불편한가: 이전에 열었던 건과 조회조건을 모두 잃으면 다시 찾아야 한다. 반대로 마지막 상세 화면만 그대로 열면 새 보완 요청이나 기한 변화를 놓칠 수 있다.

이번 대안: 기본 대시보드에 최근 작업 이어보기를 두고, 마지막 건축물·동·업무유형·회차와 조회조건을 복원한다. 같은 화면에서 새 요청과 최신 상태도 확인한다. 예를 들어 “주민회관 2회차 보고서 이어보기” 옆에 “이후 보완 요청 1건”을 표시한다.

③ 지도와 업무 화면을 오가면서 같은 건을 다시 찾는다

기존 관찰: 지도, 관리자 업무, sBIM, 연계 SSIB의 화면 구조와 대상 표현이 다르다. 관련 기능은 이미 있지만, 화면을 옮길 때 같은 건축물과 회차인지 재확인해야 한다.

왜 불편한가: 관할 분포를 살펴보다 점검자료를 열거나, 보고서를 검토하다 현장 위치를 확인할 때 탐색이 끊긴다.

이번 대안: 로그인한 공간의 상단에 내 업무와 지도 분석을 둔다. 각 탭은 마지막 조회환경을 유지하고, 선택한 건축물·동·관련 점검건은 서로 연결한다. 지도에서 점검건을 열었다가 돌아오면 보던 지역과 후보를 다시 확인할 수 있다.

④ 공개 조회의 배치와 표현이 주 사용자·대상을 흐린다

기존 관찰: 현재 플랫폼은 지도·BIM·업무지원·민간 자가점검을 함께 제공한다. 앞선 가상 시안은 공개 조회를 왼쪽에 놓고 건축물 정보로 안내했다. 사용자는 업무를 왼쪽 주 경로로 두고, 조회 대상도 관리·검토가 필요한 노후건축물로 명확히 할 것을 요청했다.

왜 불편한가: 공개 조회가 먼저 보이고 대상이 일반 건축물로 표현되면, 공무원·전문기관의 반복 업무가 보조 기능처럼 읽힌다. 일반인도 이곳에서 어떤 건축물의 어떤 안전정보를 찾을 수 있는지 알기 어렵다.

이번 대안: 왼쪽에는 공무원·전문기관 업무, 오른쪽에는 노후건축물 안전진단 정보조회를 배치한다. 오른쪽은 지도(GIS)와 경량 건축물 모델(sBIM)을 이용한 비로그인 조회임을 안내한다. 기관 업무의 우선순위와 공개 조회의 목적을 첫 화면에서 함께 이해하게 하는 배치다.

⑤ 이전 화면으로 돌아가는 경로가 분명하지 않다

기존 관찰: 사용자는 시안에서 뒤로 가기 부재를 지적했다. 기존 플랫폼도 지도·업무·현장 화면의 틀이 달라, 들어온 위치로 돌아가는 경로가 일관되게 보이지 않았다.

왜 불편한가: 상세나 모델을 확인한 뒤 검색 결과를 다시 찾아야 하면 반복 탐색이 생긴다. 복귀할 때 선택한 대상이나 작성 중인 내용까지 사라지면 업무를 이어가기 어렵다.

이번 대안: 이전 화면, 검색 결과로, 점검 목록으로, 보고서로처럼 돌아갈 위치를 알 수 있는 복귀 경로를 제공한다. 이전 화면으로 돌아갈 때 검색조건·선택 대상·스크롤 위치·작성 중인 내용을 유지한다. 화면 복귀와 시안 기록 초기화를 별개 동작으로 구분한다.

3. 로그인 후 대시보드와 복원 규칙

업무는 실제 유형과 소속 범위 안에서 보여준다

공무원 대시보드는 정기점검, 소규모 노후건축물 점검, 3종건축물 지정 실태조사 등 실제 업무유형과 기존 절차를 유지한다. 그 안에서 기한 확인, 기관 확인, 공유 결과 검토가 필요한 건을 보여준다. 전문기관은 담당 점검의 현장 준비, 자료 확인, 보고서 준비, 보완 대응을 이어간다.

진입 화면에서 안전진단 정보조회라는 안내를 쓰더라도 각 점검·실태조사를 모두 법정 안전진단으로 바꾸어 부르지 않는다. **건축물 생애이력 관리시스템(BLCM)**의 고유명칭, 업무별 보고·검토 절차와 상태 의미도 유지한다. 플랫폼 내부 결과 검토 완료는 BLCM의 법정 제출·접수·승인 완료와 구분한다.

내 담당과 관할 전체 또는 기관 전체의 조회범위를 구분한다. 특정 직원의 일만 보여주면 공동 업무나 담당자 변경 상황을 놓칠 수 있다. 조회범위는 화면에 계속 표시하고, 이용 가능한 범위는 계정 권한에 따른다.

복원할 내용과 다시 확인할 내용을 나눈다

복원할 작업 맥락 재접속 시 새로 확인할 내용
마지막 업무유형·조회범위·검색조건 새로 도착한 요청과 변경된 담당자
최근 열었던 건축물·동·점검회차 현재 보고서 버전과 검토 상태
업무·지도 탭의 마지막 조회환경 점검기한·사업 일정·내부 회신 일정
이어서 작성하던 가상 작업 해당 건을 계속 열람·작성할 수 있는지

이전 화면이 작성 중이었다고 해서 현재도 작성 가능한 것은 아니다. 이미 결과 검토가 끝났다면 최신 상태와 공유본을 보여주고, 접근 범위가 달라졌다면 설명과 현재 이용 가능한 업무로 연결한다.

복원된 조회조건은 화면에서 확인하고 초기화할 수 있게 한다. “지난번 조건이 남아 있어서 건이 안 보이는 상황”을 줄이기 위해 선택한 업무유형·지역·상태와 결과 수를 함께 표시한다.

이번 시안의 보관 범위

이번 보강 시안에서는 가상 작업과 조회환경을 해당 브라우저의 로컬 기록으로 보관하여 로그아웃·재접속 복원을 체험하도록 설계한다. 실제 안전워치·SSIB·BLCM 서버와 통신하거나 운영 데이터를 저장하는 기능은 아니다.

로그아웃은 접속을 끝내는 동작이고, 시안 기록 초기화는 가상 작업을 처음 상태로 되돌리는 동작으로 구분한다. 다른 브라우저나 기기까지 작업이 이어지는 실제 계정 동기화는 이번 로컬 시안의 범위에 포함하지 않는다.

4. 내 업무와 지도 분석의 연결

내 업무는 처리할 건을 찾고 현장자료·보고서·공유 결과를 확인하는 작업 공간이다. 지도 분석은 관할 분포, 후보의 위치, 주변 맥락과 선별 근거를 검토하는 작업 공간이다.

두 탭에서 같은 건축물을 선택했을 때는 이름·주소·동과 관련 업무가 일치해야 한다. 다만 지도에서 보는 후보와 법정 점검건은 같은 의미가 아니므로, 지도 상세에는 어떤 점검유형·회차와 연결되는지 표시한다.

예시 흐름은 다음과 같다.

  1. 공무원이 내 업무에서 소규모 점검 목록을 확인한다.
  2. 지도 분석으로 옮겨 해당 건물의 위치와 후보 근거를 본다.
  3. 관련 점검건을 열어 이전 결함·이번 회차 자료를 확인한다.
  4. 지도 탭으로 돌아와 같은 후보와 보던 지역을 이어서 검토한다.

탭을 바꿀 때마다 모든 조건을 초기화하지 않는다. 지도 확대 수준처럼 해당 탭에 필요한 설정은 별도로 유지하고, 건축물·업무 식별정보는 공통으로 연결한다.

뒤로 가기는 탐색 위치를 복원한다

화면 안의 복귀 버튼과 브라우저 뒤로 가기는 같은 건축물·동·회차와 원래 조회조건으로 돌아가야 한다. 현장 근거를 작성하다 다른 자료를 보고 돌아왔을 때는 그 근거의 작성 중인 내용을 이어서 보여준다. 서로 다른 부재·사진의 설명이 섞이지 않도록 작성 내용도 대상별로 구분한다.

이전 화면으로 돌아가는 것은 이미 공유한 보고서를 취소하거나 검토 상태를 과거로 되돌리는 동작이 아니다. 탐색 위치와 작성 맥락은 복원하되, 현재 업무 상태와 공유 버전은 최신 상태로 보여준다.

5. 보조 경로: 노후건축물 안전진단 정보조회

초기 화면 오른쪽 보조 영역에서 관리·검토 대상 노후건축물의 주소 검색과 GIS 지도 조회를 제공한다. 특정 대상 건축물을 알고 온 사람은 주소 검색으로 접근하고, 지역의 관리·검토 대상 분포를 살펴보려는 사람은 지도를 이용한다. 결과 목록과 지도에는 같은 조회 범위와 대상 수를 표시한다.

대상 건축물 요약에는 관리·검토 대상에 포함된 이유, 공개 가능한 기본 정보, 자료 출처·기준일, 공개된 점검·진단 정보를 정리한다. 대상 사유가 확인되지 않았다면 추측하지 않고 확인 상태를 표시한다. 공개용 sBIM이 있으면 상세에서 열고, 없으면 공개용 sBIM 자료 없음으로 표시한다.

노후하다는 사실만으로 위험 건축물 또는 법정 안전진단 대상이라고 단정하지 않는다. 지도에서 관리·검토 대상으로 표시된 상태, 실제 현장 점검·진단 결과, AI 추정 결과의 의미를 각각 구분한다. 모델이나 점검자료가 없다는 사실도 미점검 또는 안전 판정으로 해석하지 않게 안내한다.

공개 BIM의 범위는 별도 확인이 필요하다

제공 PDF 11·19·27쪽은 대국민·거주자 서비스와 건축물 정보 제공 구상을 뒷받침한다. 그러나 현재 실제 BIM을 비로그인 사용자에게 모두 공개할 수 있다는 정책·범위는 확인되지 않았다. 13·25쪽의 BIM은 건물 외형뿐 아니라 부재와 속성정보도 포함한다.

따라서 이번 시안의 공개 sBIM은 외형·층 구분을 보여주는 별도의 가상 공개용 모델이다. 실제 서비스에서는 외형 3D, 실내 공간, 구조 속성, 결함 기록 등 자료별로 제공 범위를 정한 뒤 화면에 반영해야 한다. 공개 GIS 지도와 업무 지도는 같은 대상 건축물 식별을 활용하되, 노출 정보와 수행 가능한 업무를 구분한다.

건물을 보다가 로그인해도 목적지를 유지한다

공개 화면에서 특정 건물을 보고 업무 로그인을 선택했다면, 로그인 후 해당 건물의 업무 맥락으로 이어진다. 평소의 기본 진입은 대시보드이지만, 이번 방문에서 사용자가 명시적으로 선택한 목적지가 있으면 그 목적지를 우선한다. 접근 가능한 업무가 없다면 그 이유와 공개 정보·업무 홈으로 가는 경로를 안내한다.

6. 검증 범위와 이번 보강의 확인 항목

수정한 가상 시안에서 공개 조회·로그인 목적지·업무 복원·공유·보완 흐름 25개 확인과 업무 우선 배치·뒤로가기 관련 20개 확인을 통과했다. 추가 확인에는 검색조건·스크롤·BIM 시점·근거별 초안 복원, 브라우저 뒤로/앞으로 가기, 단독 링크 복귀, 모바일 업무 우선 배치가 포함된다. 아래는 실제 사용자 평가와 운영 구현에서 이어서 확인할 기준이다. 실제 운영 사이트의 저장·권한·공개 범위 검증과는 구분한다.

  • 첫 화면 왼쪽과 좁은 화면의 위쪽에서 공무원·전문기관 업무가 주 경로로 읽히는가.
  • 공무원과 전문기관이 로그인하면 각 역할의 대시보드와 조회범위가 보이는가.
  • 로그아웃 후 재접속해도 최근 작업·조회조건이 이어지고, 최신 업무 상태를 함께 읽을 수 있는가.
  • 내 업무와 지도 분석을 왕복해도 건축물·동·점검회차와 각 탭의 조회환경이 유지되는가.
  • 오른쪽 보조 경로에서 일반인이 로그인 없이 관리·검토 대상 노후건축물의 주소 검색·공개 GIS 지도·안전진단 정보·가상 공개 sBIM을 열 수 있는가.
  • 노후·검토 대상·현장 결과·법정 상태가 서로 같은 의미처럼 표시되지 않는가.
  • 공개 건물에서 로그인하면 선택한 건물의 맥락이 유지되는가.
  • 상세·근거·모델 화면에서 이전 화면으로 돌아갈 수 있고, 검색조건·대상·작성 중인 내용이 유지되는가.
  • 시안 기록 초기화와 로그아웃의 결과가 구분되고, 실제 서버 저장으로 오해하지 않게 안내되는가.

보강의 목표: 공무원·전문기관의 노후건축물 관리 업무를 첫 화면의 중심에 두고, 일반인은 오른쪽 보조 경로에서 공개 가능한 안전진단 정보를 조회한다. 어느 경로에서도 대상과 작업 내용을 잃지 않고 이전 화면으로 돌아올 수 있게 한다.
